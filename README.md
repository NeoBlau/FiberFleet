# FiberFleet

Программа для планирования, учёта и контроля сервисного обслуживания тягачей и прицепов.
Это веб-приложение (PWA): открывается в браузере на ПК, планшете и смартфоне, ставится как приложение на Windows, macOS, Android и iOS и работает без сети с последующей синхронизацией.

## Возможности (по разделам ТЗ)

| Требование ТЗ | Где в программе |
|---|---|
| Учёт тягачей и прицепов: госномер, марка, модель, пробег, история | «Тягачи и прицепы» → карточка ТС (история работ, ремонты, запчасти, журнал пробега) |
| Добавление, редактирование, удаление ТС | Там же; ТС с историей уходит в архив, история не теряется |
| База фиксированных работ (~200) с обновлением | «Справочник работ»: 168 работ из прайса + 16 дополнительных, норма, цена с НДС, ЗП, допуск |
| Дефектовка с фиксацией неисправностей (отметка галочкой) | «Дефектовка» — форма повторяет вашу «Дефектную ведомость», колёса и оси отмечаются на схеме |
| Автоматический план ремонта и зона осмотра | Работы подбираются по правилам; для каждого дефекта показано, куда смотреть и что проверить |
| Рекомендация проверить связанные узлы (суппорт → ось) | Связанные проверки добавляются в план, непроверенные связанные пункты подсвечиваются |
| Приоритеты и сроки — автоматически, ошибка при невозможности | 4 уровня приоритета; ошибки: противоречие приоритета и сроков, срок в прошлом, позже даты выпуска, нет допущенного исполнителя, загрузка не укладывается в срок. План с ошибками не утверждается |
| Ручная корректировка плана | Карточка ремонта: приоритет, срок, норма, цена, очередность, добавление/удаление работ |
| Распределение задач по компетенциям, доступам и загрузке | Планировщик учитывает допуски, специализацию, текущую загрузку и средний коэффициент времени сотрудника (уточняется по факту) |
| Ручное переназначение администратором | Карточка работы: исполнитель и фиксированное время начала |
| Расписание сотрудников, вывод на монитор оператора | «Расписание» (день/неделя/список) и «Экран оператора» с автообновлением |
| Статусы работ, отметка выполнения | Начать / пауза / выполнено (фактическое время, пробег) / отмена |
| Учёт установленных запчастей, выгрузка в 1С | «Запчасти и 1С»: импорт номенклатуры (XLSX, CSV, CommerceML), выгрузка XML/Excel/CSV и HTTP API |
| Пробег на момент ремонта, анализ пробега, рекомендации ТО | «Пробег и ТО»: интервалы по маркам, среднесуточный пробег, прогноз даты, «просрочено/скоро» |
| Отчёты с ценами и зарплатами за любой период, Excel/PDF | «Отчёты»: работы, зарплата и выработка, запчасти, состояние ТС, ремонты; выгрузка Excel, PDF, CSV; заказ-наряд в PDF |
| Облако, несколько пользователей, разные устройства | Один сервер, вход по логину, 4 роли, адаптивный интерфейс |
| Работа без сети с синхронизацией | Данные кэшируются на устройстве; изменения копятся в очереди и отправляются при появлении связи (без дублей) |

Начальные данные загружены из ваших файлов: 50 тягачей и 49 прицепов со сцепками, прайс работ с допусками сотрудников (Чешуин, Жуйков, Жужгин, Сластунов, Козырев, Козлов, токарь, сторонний сервис).

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run build      # собрать интерфейс
npm start          # http://localhost:8080
```

Для разработки: `npm run dev` (API на 8080, интерфейс на 5173).

### Учётные записи по умолчанию

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin (или `FF_ADMIN_PASSWORD`) | Администратор |
| operator | operator | Оператор |
| master | master | Мастер-приёмщик |
| slastunov | slastunov | Слесарь (пример) |

Сразу смените пароли (клик по имени внизу меню). Демо-пользователей можно не создавать: `FF_DEMO_USERS=0` при первом запуске.

### Установка на Linux-сервер

Полная инструкция: [docs/DEPLOY.md](docs/DEPLOY.md). Коротко: `sudo bash deploy/install.sh fleet.ваш-домен.ru you@почта.ru`.

### Развёртывание через Docker

```bash
docker compose up -d --build
```

База хранится в `./data/fiberfleet.db`. Для работы установки PWA на телефоны и офлайн-режима сервер должен открываться по HTTPS (обычный обратный прокси: Caddy, nginx + Let's Encrypt). Резервная копия базы скачивается в «Настройки → Резервная копия».

Переменные окружения: `PORT` (8080), `FF_DATA_DIR` (папка базы), `FF_DB` (путь к файлу базы), `FF_ADMIN_PASSWORD`, `FF_DEMO_USERS`.

### Установка на устройства

- **Windows / macOS** (Chrome, Edge): значок «Установить приложение» в адресной строке.
- **Android** (Chrome): меню → «Добавить на главный экран».
- **iPhone / iPad** (Safari): «Поделиться» → «На экран „Домой“».

## Обмен с 1С

- **Номенклатура в FiberFleet**: файл XLSX/CSV из 1С (колонки «Код», «Артикул», «Наименование», «Ед. изм.», «Цена») или CommerceML (`import.xml`, `offers.xml`). Сопоставление по коду 1С.
- **Установленные запчасти в 1С**: XML (документ на каждый заказ-наряд: госномер, пробег, строки с кодом, количеством, ценой), Excel или CSV. Выгруженные строки отмечаются, повторно не выгружаются.
- **Автоматический обмен по HTTP** (для обработки в 1С):
  - `POST /api/auth/login` `{"login","password"}` → `token`
  - `GET /api/onec/export?format=json&only_new=1&mark=1` — новые установленные запчасти
  - `POST /api/onec/parts` — массив `[{code, article, name, unit, price}]`
  - заголовок `Authorization: Bearer <token>`

Загрузку XML в саму 1С делает обработка на стороне 1С — её пишет ваш 1С-программист по описанию формата выше (пример — в выгрузке).

## Что стоит проверить и настроить

- **Работы с пометкой «Добавлено FiberFleet»** (16 шт., категория «Дополнительные работы»): их не было в прайсе, а правилам дефектовки они нужны (поиск утечки воздуха, АКБ, тент, шиномонтаж и т. п.). Норма и цена посчитаны от нормо-часа 2000 ₽ — проверьте.
- **Интервалы ТО** (раздел «Пробег и ТО → Правила ТО»): по умолчанию 50 000 км / год, FAW — 40 000 км, регулировка клапанов — 120 000 км. Замените на регламенты ваших марок.
- **Тип тормозов**: KOGEL заведены с барабанными тормозами, SCHMITZ и тягачи — с дисковыми (DAF CF85 — барабанные). От этого зависит, какие работы попадают в план. Поправьте в карточке ТС, если не так.
- **Пробег**: в исходном списке пробега нет. Он записывается при каждой дефектовке; до этого ТО показывается как «нет данных».
- **Рабочее время**: пн–пт, 8:00–17:00, обед 12–13, Москва. Меняется в «Настройках».

## Регистрация в Роспатенте

Пакет документов — в [docs/rospatent](docs/rospatent): инструкция по подаче, реферат, депонируемые материалы (исходный текст, 70 листов), сведения для заявления, согласие автора, договор об отчуждении, служебное задание. После заполнения `tools/rospatent.config.json` документы пересоздаются командами `node tools/rospatent-deposit.mjs` и `node tools/rospatent-docs.cjs`.

## Структура

```
server/            API (Node.js, Express, SQLite)
  domain/          checklist.js — шаблон ведомости и правила «дефект → работы → зона осмотра → связанные проверки»
                   planner.js — план ремонта и проверка противоречий
                   scheduler.js — распределение задач и расписание
                   calendar.js — рабочий календарь
                   maintenance.js — пробег и ТО
  services/        ремонты, отчёты (Excel/PDF/CSV)
  routes/          REST API
  seed/            данные из ваших файлов (парк ТС, прайс)
  test/            сквозные тесты: npm test
client/            интерфейс (React, PWA)
```

Таблицы БД соответствуют разделу 5 ТЗ: `tractors`, `trailers`, `tasks` («Работы»), `employees`, `parts` и `installed_parts` («Запчасти» с источником 1С), `schedule` («Расписание»), плюс `repair_orders` (дефектовка и план), `work_types` (справочник), `mileage_log`, `maintenance_rules`, `users`.
