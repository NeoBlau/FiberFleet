# FiberFleet

Программа для планирования, учёта и контроля сервисного обслуживания тягачей и прицепов.
Это веб-приложение (PWA): открывается в браузере на ПК, планшете и смартфоне, ставится как приложение на Windows, macOS, Android и iOS и работает без сети с последующей синхронизацией.

## Возможности (по разделам ТЗ)

| Требование ТЗ | Где в программе |
|---|---|
| Учёт тягачей и прицепов: госномер, марка, модель, пробег, история | «Тягачи и прицепы» → карточка ТС (история работ, ремонты, запчасти, журнал пробега) |
| Добавление, редактирование, удаление ТС | Там же; ТС с историей уходит в архив, история не теряется |
| База фиксированных работ (~200) с обновлением | «Справочник работ»: 168 работ из прайса + 16 дополнительных, норма, цена с НДС, ЗП, допуск |
| Дефектовка с фиксацией неисправностей (отметка галочкой) | «Дефектовка» — форма повторяет вашу «Дефектную ведомость», колёса и оси отмечаются на схеме |
| Автоматический план ремонта и зона осмотра | Работы подбираются по правилам; для каждого дефекта показано, куда смотреть и что проверить |
| Рекомендация проверить связанные узлы (суппорт → ось) | Связанные проверки добавляются в план, непроверенные связанные пункты подсвечиваются |
| Приоритеты и сроки — автоматически, ошибка при невозможности | 4 уровня приоритета; ошибки: противоречие приоритета и сроков, срок в прошлом, позже даты выпуска, нет допущенного исполнителя, загрузка не укладывается в срок. План с ошибками не утверждается |
| Ручная корректировка плана | Карточка ремонта: приоритет, срок, норма, цена, очередность, добавление/удаление работ |
| Распределение задач по компетенциям, доступам и загрузке | Планировщик учитывает допуски, специализацию, текущую загрузку и средний коэффициент времени сотрудника (уточняется по факту) |
| Ручное переназначение администратором | Карточка работы: исполнитель и фиксированное время начала |
| Расписание сотрудников, вывод на монитор оператора | «Расписание» (день/неделя/список) и «Экран оператора» с автообновлением |
| Статусы работ, отметка выполнения | Начать / пауза / выполнено (фактическое время, пробег) / отмена |
| Учёт установленных запчастей, выгрузка в 1С | «Запчасти и 1С»: импорт номенклатуры (XLSX, CSV, CommerceML), выгрузка XML/Excel/CSV и HTTP API |
| Пробег на момент ремонта, анализ пробега, рекомендации ТО | «Пробег и ТО»: интервалы по маркам, среднесуточный пробег, прогноз даты, «просрочено/скоро» |
| Отчёты с ценами и зарплатами за любой период, Excel/PDF | «Отчёты»: работы, зарплата и выработка, запчасти, состояние ТС, ремонты; выгрузка Excel, PDF, CSV; заказ-наряд в PDF |
| Облако, несколько пользователей, разные устройства | Один сервер, вход по логину, 4 роли, адаптивный интерфейс |
| Работа без сети с синхронизацией | Данные кэшируются на устройстве; изменения копятся в очереди и отправляются при появлении связи (без дублей) |

Начальные данные загружены из ваших файлов (сводка «АВТО» от 02.10.2026): 59 тягачей и 58 прицепов со сцепками, пробегом и заметками, прайс работ с допусками сотрудников (Чешуин, Жуйков, Жужгин, Сластунов, Козырев, Козлов, токарь, сторонний сервис).

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run build      # собрать интерфейс
npm start          # http://localhost:8080
```

Для разработки: `npm run dev` (API на 8080, интерфейс на 5173).

### Учётные записи по умолчанию

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin (или `FF_ADMIN_PASSWORD`) | Администратор |
| operator | operator | Оператор |
| master | master | Мастер-приёмщик |
| slastunov | slastunov | Слесарь (пример) |

Сразу смените пароли (клик по имени внизу меню). Демо-пользователей можно не создавать: `FF_DEMO_USERS=0` при первом запуске.

Для восстановления исходных паролей в локальной базе этой копии остановите сервер и выполните `npm run reset-local-passwords`. Команда меняет пароли только в базе, выбранной через `FF_DATA_DIR`/`FF_DB` (по умолчанию `./data/fiberfleet.db`), и восстанавливает `admin`, `operator`, `master`, `slastunov`.

### Установка на Linux-сервер

Полная инструкция: [docs/DEPLOY.md](docs/DEPLOY.md). Коротко: `sudo bash deploy/install.sh fleet.ваш-домен.ru you@почта.ru`.

### Развёртывание через Docker

```bash
docker compose up -d --build
```

База хранится в `./data/fiberfleet.db`. Для работы установки PWA на телефоны и офлайн-режима сервер должен открываться по HTTPS (обычный обратный прокси: Caddy, nginx + Let's Encrypt). Резервная копия базы скачивается в «Настройки → Резервная копия».

Переменные окружения: `PORT` (8080), `FF_DATA_DIR` (папка базы), `FF_DB` (путь к файлу базы), `FF_ADMIN_PASSWORD`, `FF_DEMO_USERS`.

### Установка на устройства

- **Windows / macOS** (Chrome, Edge): значок «Установить приложение» в адресной строке.
- **Android** (Chrome): меню → «Добавить на главный экран».
- **iPhone / iPad** (Safari): «Поделиться» → «На экран „Домой“».

## Актуализация парка

Список ТС хранится в `server/seed/fleet.json`. При первом запуске база заполняется из него автоматически. Чтобы загрузить новые ТС, сцепки, пробег и заметки в уже работающую базу (ничего не удаляется, история сохраняется):

```bash
node tools/fleet-update.mjs --dry-run   # посмотреть изменения
node tools/fleet-update.mjs             # применить
```
На сервере: `cd /opt/fiberfleet && runuser -u fiberfleet -- env FF_DATA_DIR=/var/lib/fiberfleet node tools/fleet-update.mjs`.

## Актуализация прайса (справочник работ)

Прайс хранится в `server/seed/catalog.json`. Чтобы перенести новые нормы времени, цены, ЗП и допуски в работающую базу (работы не удаляются, история ремонтов не меняется; добавляются новые работы и сотрудники из допусков; стоимость нормо-часа 2000 → 2640 ₽, если её не меняли):

```bash
node tools/catalog-update.mjs --dry-run      # посмотреть изменения
node tools/catalog-update.mjs                # применить
node tools/catalog-update.mjs --apply-open   # + пересчитать ещё не начатые работы
```
На сервере: `cd /opt/fiberfleet && runuser -u fiberfleet -- env FF_DATA_DIR=/var/lib/fiberfleet node tools/catalog-update.mjs`.

## Обмен с 1С

- **Номенклатура в FiberFleet**: файл XLSX/CSV из 1С (колонки «Код», «Артикул», «Наименование», «Ед. изм.», «Цена») или CommerceML (`import.xml`, `offers.xml`). Сопоставление по коду 1С.
- **Установленные запчасти в 1С**: XML (документ на каждый заказ-наряд: госномер, пробег, строки с кодом, количеством, ценой), Excel или CSV. Выгруженные строки отмечаются, повторно не выгружаются.
- **Автоматический обмен по HTTP** (для обработки в 1С):
  - `POST /api/auth/login` `{"login","password"}` → `token`
  - `GET /api/onec/export?format=json&only_new=1&mark=1` — новые установленные запчасти
  - `POST /api/onec/parts` — массив `[{code, article, name, unit, price}]`
  - заголовок `Authorization: Bearer <token>`

Загрузку XML в саму 1С делает обработка на стороне 1С — её пишет ваш 1С-программист по описанию формата выше (пример — в выгрузке).

## Что стоит проверить и настроить

- **Работы с пометкой «Добавлено FiberFleet»** (16 шт., категория «Дополнительные работы»): их не было в прайсе, а правилам дефектовки они нужны (поиск утечки воздуха, АКБ, тент, шиномонтаж и т. п.). Норма и цена посчитаны от нормо-часа 2000 ₽ — проверьте.
- **Интервалы ТО** (раздел «Пробег и ТО → Правила ТО»): по умолчанию 50 000 км / год, FAW — 40 000 км, регулировка клапанов — 120 000 км. Замените на регламенты ваших марок.
- **Тип тормозов**: KOGEL заведены с барабанными тормозами, SCHMITZ и тягачи — с дисковыми (DAF CF85 — барабанные). От этого зависит, какие работы попадают в план. Поправьте в карточке ТС, если не так.
- **Пробег**: в исходном списке пробега нет. Он записывается при каждой дефектовке; до этого ТО показывается как «нет данных».
- **Рабочее время**: пн–пт, 8:00–17:00, обед 12–13, Москва. Меняется в «Настройках».

## Регистрация в Роспатенте

Пакет документов — в [docs/rospatent](docs/rospatent): инструкция по подаче, реферат, депонируемые материалы (исходный текст, 70 листов), сведения для заявления, согласие автора, договор об отчуждении, служебное задание. После заполнения `tools/rospatent.config.json` документы пересоздаются командами `node tools/rospatent-deposit.mjs` и `node tools/rospatent-docs.cjs`.

## Структура

```
server/            API (Node.js, Express, SQLite)
  domain/          checklist.js — шаблон ведомости и правила «дефект → работы → зона осмотра → связанные проверки»
                   planner.js — план ремонта и проверка противоречий
                   scheduler.js — распределение задач и расписание
                   calendar.js — рабочий календарь
                   maintenance.js — пробег и ТО
  services/        ремонты, отчёты (Excel/PDF/CSV)
  routes/          REST API
  seed/            данные из ваших файлов (парк ТС, прайс)
  test/            сквозные тесты: npm test
client/            интерфейс (React, PWA)
```

Таблицы БД соответствуют разделу 5 ТЗ: `tractors`, `trailers`, `tasks` («Работы»), `employees`, `parts` и `installed_parts` («Запчасти» с источником 1С), `schedule` («Расписание»), плюс `repair_orders` (дефектовка и план), `work_types` (справочник), `mileage_log`, `maintenance_rules`, `users`.

### Обновление установки без Git (systemd)

Если `deploy/update.sh` сообщает, что `/opt/fiberfleet` не Git-клон, используйте от root
`bash deploy/update-archive.sh`. Для получения самого скрипта сначала скачайте его из
репозитория в отдельный файл, а не запускайте установщик заново. Скрипт по умолчанию
устанавливает проверенный коммит `a04cb0f4655f09e74ffd6a96cef8388022d018a4`;
другой полный SHA можно передать первым аргументом.

Новая версия собирается в отдельной папке до остановки службы. Затем создаётся и
проверяется SQLite-копия фактической базы из `/etc/fiberfleet.env`. Заменяются только
программные компоненты; настройки `/etc`, `.env`, `data` и `.git` сохраняются.
Предыдущие компоненты остаются в `/opt/fiberfleet/orig/<дата>`, база — в
`/var/backups/fiberfleet/fiberfleet_before_update_<дата>.db`. Если запуск не прошёл
проверку, возвращаются прежние файлы программы. База автоматически не откатывается.
Скрипт предназначен для стандартной службы systemd `fiberfleet`, не для Docker.

Изолированная проверка успешного обновления и отказов загрузки, сборки, резервного
копирования и запуска: `python3 deploy/test-update-archive.py`. Системные команды
в проверках подменены; пользовательские настройки и содержимое SQLite проверяются
до и после каждого сценария.

### Пересчёт стоимости и зарплаты

При изменении нормы работы автоматически рассчитываются цена с НДС
(норма × стоимость нормо-часа) и зарплата (рассчитанная цена × доля ЗП).
Расчёт виден в форме до сохранения и повторяется на сервере. Для диапазона норм
пересчитываются обе границы. Суммы округляются до целого рубля.

В настройках доля зарплаты вводится в процентах: `40` означает 40 %.
Изменение ставки нормо-часа или доли ЗП пересчитывает весь справочник, включая
ранее вручную скорректированные суммы, и ещё не начатые задания из справочника.
Начатые, приостановленные, завершённые и отменённые задания сохраняют свои суммы.
Обычное обновление программы само по себе не заменяет сохранённые тарифы.

### Пауза ремонта и срочная машина

В «Ремонтах» отметьте нужные строки (или «Выбрать все ремонты») и нажмите
«Приостановить ремонт». Ограничения на число выбранных ID в операции нет;
кнопка также доступна в карточке ремонта. Причина паузы необязательна.
Пауза исключает оставшиеся работы ремонта из распределения и освобождает
слесарей. Выполненные работы, суммы и нормы сохраняются. Рабочее время до паузы
записывается с указанием сотрудника; ожидание не включается в фактические часы.

Срочный ремонт отметьте кнопкой «Срочно». В «Расписании» нажмите
«Перераспределить слесарей — план на сегодня». План перестраивается от текущего
времени по рабочему календарю, с учётом допусков, специализации, занятости,
ручных назначений и последовательности операций. Критические работы P1
остаются впереди срочного ремонта. Ни одна не выбранная для паузы выполняемая
работа автоматически не прерывается. Рядом с планом показаны работы, которые
не завершатся сегодня, их ожидаемые окончания и задания без назначения.

«Возобновить ремонт» возвращает оставшиеся работы в очередь; автоматического
старта таймера нет. Ранее вручную приостановленные отдельные задания остаются
на паузе. Для продолжения конкретной работы слесарь нажимает «Начать».
Новые поля и журнал рабочих интервалов добавляются в существующую базу
без удаления ремонтов. Точные интервалы старых пауз до обновления не
восстанавливаются, если раньше они не записывались.

### Экран оператора: несколько дней и ручные назначения

На экране оператора выберите начальную дату и период: день, 3 дня, неделю или
две недели. Таблица показывает всех сотрудников и все назначения выбранного
периода, без прежнего ограничения в четыре следующих задания. Длительная работа
показана по затронутым рабочим дням; загрузка считается отдельно для каждого дня.
Дата и время соответствуют часовому поясу, заданному в настройках сервиса.

Нажмите «Редактировать расписание» и выберите плановую работу. Можно изменить
слесаря, начало, приоритет и оценку окончания. По умолчанию окончание рассчитывается
по оставшейся норме, коэффициенту сотрудника и рабочему календарю; можно указать
окончание вручную. Это меняет окно в плане, а не норму, стоимость, зарплату или
фактически отработанное время. Ручное назначение закрепляется и переживает общий
пересчёт. Для возврата в общую очередь есть «Вернуть автопланирование».

Сохранение обновляет общее расписание, автоматически перестраивает незакреплённые
работы, обновляет сроки ремонтов, карточки и сводку. На экране показывается число
изменённых назначений и предупреждения по срокам или работам без назначения.
Сохранение полностью откатывается при конфликте со слесарем, недостаточном допуске,
превышении числа работников на машине или нарушении порядка операций.
Начатые, завершённые и приостановленные работы этим редактором не изменяются.
Редактирование доступно при наличии обоих прав `plan.write` и `tasks.reassign`.
Слесарь получает в многодневном мониторе только своё расписание. Данные экрана
обновляются автоматически каждые 30 секунд; при конфликте двух операторов требуется
обновить устаревшую форму, а не перезаписывать чужое изменение.

### Изменение допусков при существующих назначениях

Сохранение допуска в справочнике автоматически пересчитывает открытое расписание.
Обычные ещё не начатые задания назначаются сотрудникам с действующим допуском.
Явный список сотрудников для внутренних работ не расширяется за счёт совпадения
квалификации другого слесаря. Изменение только обязательной квалификации тоже
запускает пересчёт.

Ручное назначение или закреплённое время не отменяют требований допуска.
Если сотрудник потерял допуск, его ещё не начатая вручную назначенная работа
снимается с расписания и получает конфликт. Само ручное пожелание сохраняется
в карточке для решения оператором: выберите допустимого сотрудника или снимите
ручное назначение. Если допущенных сотрудников нет, автоматическая работа
остаётся без назначения с объяснением причины.

Уже выполняемая работа не переименовывается задним числом и не переносится
на другого сотрудника автоматически. На главной, в ремонте и на экране оператора
видно предупреждение о конфликте. Для смены исполнителя приостановите работу,
назначьте допустимого слесаря и продолжите. Начать или продолжить задание без
действующего допуска нельзя. Учтённые интервалы прежнего исполнителя сохраняются;
изменение справочника не меняет завершённые работы.

После установки исправления повторно сохраните допуск либо пересчитайте расписание,
чтобы обработать ранее сохранённые недопустимые назначения. F5 только загружает
актуальные данные; это не отдельная команда перепланирования.
